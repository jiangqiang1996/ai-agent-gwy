# pivot: shift tutoring system toward knowledge summaries and persona-aware guidance

## Overview

本轮需求不是小修小补，而是一次明确的产品方向调整：系统从“练题/刷题闭环优先”转向“基础知识总结与相关知识点梳理优先，经典例题作为辅助”。

这会影响用户画像字段、状元代理体系、导出能力、积分与计时机制，以及编排器的默认工作重心。

## Problem Frame

当前系统虽然已经具备练题、计时、判题、积分、学习记录等能力，但新的产品目标更偏向：

- 帮用户总结基础知识点
- 组织相关知识点和知识框架
- 在需要时附带经典例题或示例
- 根据用户真实身份场景（在职 / 应届）给出更贴近现实的状元经验视角
- 在需要导出时，提供更高质量的 Markdown / HTML 产物

因此，原先围绕“刷题闭环”的积分、等级、计时器等机制不再是系统核心，甚至部分功能需要被移除或降级。

## Product Goals

1. 让系统的核心输出从“做一道题”转向“讲清一个知识点 / 一组相关知识点”。
2. 让状元代理与用户身份更强绑定，减少与用户现实场景不匹配的建议。
3. 提供稳定的导出能力，支持把当前会话中有价值的内容落成 Markdown 或 HTML 文件。
4. 清理与备考目标无关的积分、等级、奖惩设计，减少噪音。
5. 保留“经典例题/示例”能力，但不再把系统定位为刷题工具。

## Requirements

### R1. 用户资料增加身份字段

用户资料新增一个可选身份字段，用于表示：

- `working`：在职
- `campus`：应届生

该字段用于影响代理选择、建议内容和后续工作流。

### R2. 状元代理按身份与考试类型细分

状元代理从当前的 2 个固定角色，细分为以下骨架：

- 在职国考状元
- 应届国考状元
- 在职省考状元
- 应届省考状元

行为规则：

- 用户是 `working` 时，只启用在职相关状元代理
- 用户是 `campus` 时，只启用应届相关状元代理

### R3. 省考状元需要按地区动态收敛

当用户提供了 `region` 后，所有“省考状元”能力都应当带上地区人格化上下文。

例如：

- 重庆省考在职状元
- 江苏省考应届状元

这里的“动态”优先解释为：

- 由编排器在运行时注入地区 persona 上下文
- 不要求为每个省份都静态维护独立 agent 文件

### R4. 新增 Markdown / HTML 导出技能

新增两个技能，导出目录统一为项目根目录下的 `output/`：

- 一个用于导出 Markdown 文件
- 一个用于导出 HTML 文件

导出内容来源可以是：

- 用户明确提供的指定内容
- 当前会话中的重要内容总结
- 当前会话中的计划/方案/知识点整理结果

### R5. HTML 导出优先级规则

优先使用 HTML 导出的场景：

- 出题时优先导出 HTML 格式
- 需要绘制较复杂图示，Markdown 无法很好表达时
- 用户明确指定 HTML
- 对排版质量要求较高时

除此之外的导出场景默认使用 Markdown。

### R6. 移除积分、等级和奖惩机制

系统不再记录以下与备考主目标无关的内容：

- 积分
- 等级
- 连胜
- 基于答对/答错的奖惩反馈

与其绑定的工具逻辑、文案、文档和提示词都应移除或改造。

### R7. 系统主轴转向“知识点总结 + 经典例题”

系统默认优先做的是：

- 基础知识总结
- 相关知识点展开
- 知识框架梳理
- 易错点与辨析
- 经典例题或代表性示例补充

而不是默认进入刷题练习模式。

### R8. 移除刷题导向计时器

既然核心不再是刷题训练，则原有计时器机制不再是主要功能，应从核心流程中移除。

这意味着：

- 编排器默认流程不再依赖 timer
- 与刷题闭环绑定的 attempt/timer 主路径要么移除，要么降级为非核心兼容路径

## Scope Boundaries

- 本轮不要求重新设计整个老师体系。
- 本轮不要求引入数据库或远程服务。
- 本轮不要求实现复杂富文本编辑器；导出是“把现有内容落盘”，不是做完整文档编辑平台。
- 本轮不要求给每个省份都维护一份单独的省考状元 agent 文件。
- 本轮不要求保留旧积分体系的兼容展示。

## Recommended Product Direction

### 1. 省考状元采用“静态骨架 + 动态地区注入”

建议不要尝试在插件里运行时真正注册新的 agent 实体。

更稳妥的方式是：

- 静态保留 4 个状元骨架代理
- orchestrator 根据用户 `identity + examTypes + region`，在调用时为省考状元附加地区 persona 上下文

这样可以做到“动态变成对应地区的省考状元”，同时保持当前 repo 的静态 agent 架构和可维护性。

### 2. 系统默认入口改成“总结/梳理/导出”

建议把以下意图提升为主路径：

- 总结某知识点
- 梳理某模块知识框架
- 解释相关联知识点
- 导出当前内容

而“出一道题”退到辅助路径。

## User Experience Changes

用户未来更自然的对话方式应该是：

- “帮我总结判断推理里的逻辑判断基础知识”
- “把这个知识点和相关知识点梳理成 markdown”
- “这个内容导出成 html，排版好一点”
- “我是重庆省考在职考生，帮我从我的场景来讲”

而不是默认：

- “先给我出一道题并开始计时”

## Open Questions

### Need Resolution Before Technical Planning

1. “移除计时器”是彻底删除 timer 工具，还是仅从核心流程移除并保留兼容层？
2. “出题时优先导出 HTML” 是否意味着老师出题默认直接生成文件，而不是先在对话中展示？
3. 导出技能是否需要支持覆盖文件、自动文件名、时间戳命名、追加写入等策略？
4. 用户画像中的 `working/campus` 是否允许后续随时修改，以及是否必填？
5. 省考状元的地区 persona 注入是否只影响 prompt 文案，还是还要影响代理选择与示例素材范围？

## Success Criteria

- 用户资料里可以保存身份字段，并影响状元代理选择。
- 用户有地区时，省考状元的输出能明显体现对应地区语境。
- 系统可以把指定内容或当前会话成果导出到 `output/` 下的 Markdown 或 HTML 文件。
- 积分、等级、奖惩相关逻辑和文案不再出现在核心产品流程里。
- 编排器和 README 都把“知识点总结/梳理”而不是“刷题计时”放在更中心的位置。
