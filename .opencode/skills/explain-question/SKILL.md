# 讲解题目

处理用户通过任意输入渠道提供的题目，并给出详细讲解。

## 输入渠道

- **图片**：用户上传题目图片，通过 OCR 或图像识别提取题面。
- **会话文本**：用户在对话中直接粘贴或输入题目文本。
- **外部文件**：用户提供文件路径时，优先处理 `.txt`、`.md`、`.pdf` 和图片格式；编排器通过 `read` 工具读取内容。若是 `.doc` / `.docx`，先请用户转成更稳定的格式或直接粘贴题干。

## 执行步骤

1. 识别输入渠道，从对应来源提取原始题面。
2. 将内容收敛为 `QuestionArtifact`（含 `content`、`layoutType`、`confidence`、`completeness`、`unresolvedRegions`）。
3. **确认门控**：若置信度不为"高"或完整度不为"完整"，将识别到的题目内容原文展示给用户，请用户确认、补充或纠正后再继续。
4. 若是多题文件，按编号模式或空行分隔拆分为单题，依次处理。
5. 题面完整后，交给对应老师先做知识点总结，再详细讲题。
6. 若题面不足以讲解且用户无法补全，明确告知并停止。
7. 回答结束时，如合适可建议导出，但只有用户明确要求导出时才写文件。

## 使用原则

- 这是"用户提供题目 → 你来讲题"的流程，支持图片、文字和文件三种输入。
- 不要在题面不完整时硬讲，必须先走确认门控。
- 默认把用户提供的这道题当主例题处理；只有确有帮助时才额外补 1 个经典例题。
