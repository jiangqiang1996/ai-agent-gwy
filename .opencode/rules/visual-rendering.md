# 图示渲染规范

本规则适用于所有需要生成图示、图形、题目配图的场景（知识图谱、例题讲解、导出文档等）。

## 核心原则

1. **所有视觉内容必须使用代码块渲染，禁止使用纯文本字符拼图或 HTML 元素绘图画。**
2. **禁止用纯文字描述图形外观**：凡是涉及几何形状、位置关系、空间结构、运动轨迹、图表数据的内容，必须直接用 SVG、Canvas、Mermaid、Chart.js 或 Markmap 绘制，不得用"如图所示是一个三角形""图形大致如下"等文字替代。如果某个内容可以画出来，就必须画出来。
3. **SVG/Canvas 优先**：能用 SVG 或 Canvas 绘制的图形，优先使用 SVG/Canvas，而不是文字描述或 Mermaid 等间接方式。

## 允许的渲染方式

| 方式 | 适用场景 | 语法 |
|------|---------|------|
| **SVG** | 静态几何图形、题目配图、轨迹图、展开图、三视图、标注图、数轴、坐标系 | ` ```svg ` 代码块 |
| **Canvas** | 动态/复杂绘图、动画演示、交互式图形、粒子效果 | ` ```canvas ` 代码块 |
| **Mermaid** | 流程图、思维导图、架构图、决策树 | ` ```mermaid ` 代码块 |
| **Chart.js** | 数据图表、柱状图、折线图、饼图 | ` ```chart ` 代码块 |
| **Markmap** | 大型知识结构思维导图 | ` ```markmap ` 代码块 |

## 禁止的渲染方式

- **ASCII art**：禁止用 `┌─┬─┐`、`│●│ │` 等纯文本字符拼凑图形
- **HTML 元素绘图画**：禁止用 `<div>`、`<table>`、CSS border 等拼凑图形外观
- **纯文字描述替代图**：禁止用"图1是一个三角形""如下图的三角形中"等纯文字代替实际图形绘制
- **口头描述几何关系**：禁止用"点A在点B的左上方""两条线相交于一点"等文字描述替代可视化

## 必须绘制图示的场景（举例）

以下场景必须直接绘图，不得只用文字描述：
- 几何题目中的图形（三角形、圆、多边形、坐标系等）
- 行程问题中的路线、相遇追及位置
- 工程问题中的进度条、时间线
- 排列组合中的位置关系
- 资料分析中的数据趋势图
- 图形推理中的图案规律展示
- 折纸盒展开图与立体图的对应关系
- 立体图形的三视图
- 知识框架的层级结构

## 选型指南

```
需要画什么？
├── 几何图形（三角形/圆/方框/网格/折纸盒展开图/轨迹箭头）
│   → SVG（首选，静态矢量，清晰可控）
│
├── 动态演示（动画/粒子/渐变/交互）
│   → Canvas（JS 绘图 API）
│
├── 流程/逻辑（决策树/解题步骤/分类流程）
│   → Mermaid（graph TD / flowchart）
│
├── 知识框架（层级结构/全景体系）
│   → Mermaid mindmap 或 Markmap
│
└── 数据统计（频率/对比/趋势）
    → Chart.js（bar / line / pie）
```

## 图形推理（图推）配图规范

图形推理题的配图**必须贴近公考真题难度和风格**，禁止使用过于简单的示意图作为经典例题。

### 复杂度要求

1. **禁止过于简单的图形**：不得使用"一个圆""一个三角形""一个正方形"等单元素、无变化的图形作为例题配图。公考图推题通常包含多元素组合、多规律叠加或需要仔细观察的细节差异。
2. **至少包含以下特征之一**：
   - 多个图形组成的九宫格 / 六面体 / 四选一布局
   - 元素叠加、旋转、翻转、对称等多种变换的组合
   - 复杂的线条图案（含曲线、折线、阴影填充、区域分割等）
   - 空间重构中的立体图与展开图对应关系
   - 至少 3 个以上图形元素且元素间存在可观察的规律性变化
3. **贴近真题风格**：参考历年国考/省考图形推理真题的图案复杂度和视觉信息密度，例题配图应达到真题级别的视觉丰富度。
4. **图推题配图必须用 SVG 绘制**：每个图形元素（圆、三角、方框、线段、点、箭头等）必须逐一绘制，不得用文字替代或简化。

### 题干与选项都必须绘制图形

图形推理题的**题干**和**选项（A/B/C/D）**都是图形，不得用文字描述替代：

- **题干图形**：按实际布局绘制完整的九宫格 / 行列 / 分组图（缺省位留空或标问号）
- **选项图形**：每个选项（A、B、C、D）各用一个独立的 SVG 代码块绘制完整图案，禁止用"A. 一个带阴影的三角形""B. 旋转90度的图案"等文字描述选项内容
- **选项尺寸**：建议每个选项 SVG 宽高 120~150px，保持视觉一致性
- **布局**：四个选项横向或 2×2 排列均可，但必须清晰标注 A/B/C/D

### 九宫格 / 多图布局模板

图形推理题常见布局（九宫格 3×3、行列对比、分组分类等）必须按实际布局绘制，而非只画一个图然后文字描述"其余位置类似"。

```svg

  <style>
    .cell { stroke: #333; stroke-width: 1.5; fill: none; }
    .grid-line { stroke: #666; stroke-width: 0.5; }
  </style>
  <!-- 3×3 网格 -->
  <g>
    <!-- 9 个格子，每个格子内绘制对应的图案元素 -->
  </g>
</svg>
```

## SVG 编写规范

1. 必须指定 `width`、`height` 和 `viewBox`，确保缩放不失真
2. 使用 `<style>` 统一管理样式，避免内联样式散落
3. 配色使用项目主色调：`#2563eb`（主蓝）、`#dc2626`（强调红）、`#16a34a`（正确绿）、`#9333ea`（紫色）、`#ea580c`（橙色）
4. 图形元素需有清晰标注（`<text>` 标签），不能只有图形无文字说明
5. 保持 SVG 代码整洁，合理使用 `<g>` 分组和 `transform`

## Canvas 编写规范

1. 代码中可直接使用 `canvas`（canvas 元素）和 `ctx`（2D 上下文）变量
2. **禁止**使用 `fetch`、`XMLHttpRequest`、`eval`、`import` 等访问外部资源的 API
3. 推荐使用 `requestAnimationFrame` 实现动画
4. 必须设置合理的 `canvas.width` 和 `canvas.height`

## Mermaid 编写规范

1. 节点文字简洁，不超过 15 字
2. 善用 `style` 为关键节点着色，增强可读性
3. 流程图方向优先 `TD`（从上到下），关系图可用 `LR`

## 适用范围

- 所有导出为 HTML 的文档中的图示
- 知识图谱中的配图和示意图
- 例题中的题目配图（几何图形、网格、立体图等）
- 解题过程的可视化（轨迹、标注、辅助线等）
- 对话中需要展示图形时也应优先使用 SVG 代码块
