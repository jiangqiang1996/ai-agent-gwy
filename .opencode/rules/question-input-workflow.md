# 题目输入工作流

本流程统一处理三种题目输入渠道，将用户提供的题目收敛为 `QuestionArtifact` 后交给老师代理。

## 输入渠道

### 1. 会话文本
用户在对话中直接输入或粘贴题目文本。系统直接从消息中提取题面，无需额外读取。

### 2. 外部文件
用户提供文件路径。优先支持 `.txt`、`.md`、`.pdf` 与图片格式；编排器通过 `read` 工具读取文件内容。

- 对 `.doc` / `.docx`：不要假设 `read` 能稳定解析。应先请用户转成 `.txt` / `.md` / `.pdf`，或直接粘贴题干。

**多题拆分启发式：**
- 编号模式：`1.` / `2.` / `3.` 等序号开头的行
- 空行分隔：连续空行作为题目边界
- 标题模式：`题目N`、`第N题` 等题号标题
- 边界模糊时，必须向用户确认拆分方式，不要自行猜测

### 3. 图片
用户上传题目图片。使用 OCR 或图像识别工具提取题面。仅处理用户自己上传的题目图片。

## 统一处理流程

1. 识别输入渠道，从对应来源提取原始题面。
2. 收敛为 `QuestionArtifact`（契约见 `question-artifact-contract.md`）。
3. 若题面足够完整，交给对应老师先做知识点总结，再讲本题。
4. 若有必要，可补 1 个经典例题，但不要默认重复讲两道题。
5. 若用户明确要求导出，才进入导出流程；否则只在对话中回答。

## 确认门控

在步骤 2 构建 `QuestionArtifact` 之后、步骤 3 路由到老师之前，必须检查 `confidence` 和 `completeness`：

- 若 `confidence` 不为"高" 或 `completeness` 不为"完整"，暂停路由，执行确认门控（详见 `question-artifact-contract.md`）。
- 将识别到的题目内容原文展示给用户，询问是否有误或不完整。
- 用户确认后，视回复内容更新 `QuestionArtifact` 或直接继续流程。

## 失败回退

以下情况必须明确说明无法可靠解析，并要求用户补充信息：

- 图片不清晰、题干不完整、选项残缺
- 文件无法读取、编码异常，或 `.doc` / `.docx` 无法可靠提取正文
- 表格/图文混排无法可靠识别
- 多题边界无法确定且用户未确认拆分

若当前消息没有任何可用输入，提示用户上传图片、提供文件路径或直接粘贴题干，不要假装已经看到了题目。
